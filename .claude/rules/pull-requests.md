# Pull request titles and descriptions

- **Title**: one line, imperative mood, sentence case, describing the change
  itself (e.g. "Stop calling the API 33 AdaptiveIconDrawable constructor on
  minSdk 31"). No conventional-commit prefixes, no ticket tags, no emoji.
- **Description**: what changed and why, and nothing else — no diff summaries,
  no file checklists, no test-plan theatre. If the title says it all, a
  one-line body is the right length. Length is cognitive load, not
  thoroughness.
